# 바이브코딩 4회 과정 결과물 3안 견본

기관이 세 가지 수업 결과물의 차이를 확인할 수 있도록 만든 최소 기능형 정적 사이트이다.

## 구성

- `public/index.html`: 세 안 비교
- `public/option-1/`: 화면에서 일정을 추가할 수 있지만 저장하지 않는 단일 HTML 견본
- `public/option-2/`: 브라우저 저장형 하루 기록 다이어리 웹도구
- `public/pwa/`: 날씨 참고 일정 기록장 PWA
- `scripts/update-weather.mjs`: 기상청 단기예보 JSON 생성
- `.github/workflows/deploy-pages.yml`: 날씨 갱신 및 GitHub Pages 배포

## 로컬 실행

`public` 폴더를 정적 웹 서버의 루트로 실행한다. 1안은 단일 HTML 파일 안에서 일정 추가까지 동작하지만 새로고침하면 초기화되고, 2안은 처음 빈 목록에서 시작해 브라우저 `localStorage`에 기록을 보존한다. PWA 설치와 서비스 워커 검증에는 `localhost` 또는 HTTPS가 필요하다.

## GitHub Pages 배포

고급 과정은 수강생마다 자신의 공공데이터포털 인증키와 GitHub 저장소를 사용한다. 계정 가입과 기상청 단기예보 API 활용 신청은 수업 전에 완료한다. 만 14세 미만 수강생은 공공데이터포털 어린이 회원 가입 과정에서 보호자 확인이 필요할 수 있으므로 기관이 사전에 안내한다.

1. 수강생 개인 저장소의 Pages 배포 원본을 `GitHub Actions`로 설정한다.
2. 개인 저장소의 비밀 설정에 `KMA_API_KEY`를 등록한다. 공공데이터포털에서 제공하는 일반 인증키의 디코딩 값을 사용한다.
3. 필요하면 저장소 변수에 `KMA_LOCATION`, `KMA_NX`, `KMA_NY`를 등록한다.
4. 기본값은 서울, 격자 좌표 `60, 127`이다.
5. `workflow_dispatch`로 직접 첫 실행을 확인한 뒤, 워크플로가 3시간마다 날씨 JSON과 정적 사이트를 갱신하게 한다.

API 키가 없으면 최초 배포에는 샘플 JSON을 사용한다. 예약 실행에서는 기존 배포를 유지한다. API 호출이나 배포가 실패해도 마지막으로 성공한 정적 사이트는 그대로 남는다.

## 공개 범위

- 수강생별 API 키는 각자의 GitHub Secret에 등록하고 브라우저 코드와 JSON에는 포함하지 않는다.
- 공개 JSON에는 예보 값, 지역, 갱신 시각, 출처만 기록한다.
- 1안은 데이터를 저장하지 않는다.
- 2안의 다이어리 기록과 3안의 일정은 서버로 보내지 않고 각 브라우저의 `localStorage`에 저장한다.
- 기관 제출용 시연에서는 실제 개인정보 대신 공개 가능한 예시 문장을 사용한다.
